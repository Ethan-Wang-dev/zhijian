# 值见

> 每半小时，找到真正值得看的内容。

值见是一个 Chrome/Chromium Manifest V3 浏览器扩展原型。它每 30 分钟自动扫描用户配置的 X 账号、X 主题和 RSS/Atom 订阅源，再交给用户自己配置的 LLM，按个人价值需求筛选出最多 5 条主推荐，并保留其他候选。

它的目标不是简单寻找点赞最多的帖子，而是回答：

> 对这个用户来说，这条内容现在是否值得阅读、思考或互动？

## 当前能力（0.2.0）

- 在 `x.com` / `twitter.com` 页面内注入值见面板
- 后台自动打开非活动的 X 搜索页，汇总指定账号的最新内容
- 后台按主题打开 X 实时搜索页，获取主题候选
- 直接读取用户配置的 RSS/Atom 订阅源
- 将多源候选统一为正文、作者、链接、时间、来源和互动指标
- 用户自定义 LLM API Base URL、模型和 API Key
- 用户用自然语言描述自己的价值需求、主题和关注账号
- LLM 按相关性、信息增量、影响、可执行性、思考价值、互动价值、证据质量和时效性评分
- 展示最多 5 条主推荐，以及可展开的其他候选
- 默认只有达到 65 分的内容才能进入主推荐，阈值可配置
- 每 30 分钟由 `chrome.alarms` 自动扫描配置源；不要求用户正在浏览某个 X 信息流
- 主推荐达到结果后发送浏览器通知
- 支持“有用 / 不太相关”反馈，反馈暂存于本地
- 当前页面分析只作为手动辅助入口

## 安装开发版

1. 打开 Chrome 的 `chrome://extensions`。
2. 打开右上角“开发者模式”。
3. 点击“加载已解压的扩展程序”。
4. 选择本项目目录。
5. 打开 `值见 → 设置`，填写自己的 OpenAI-compatible API Base URL、模型和 API Key。
6. 填写要关注的 X 账号、X 主题和 RSS/Atom 地址，并保存浏览器请求的来源访问权限。
7. 确认浏览器已经登录 X。
8. 点击扩展弹窗中的“立即扫描全部配置源”进行首次测试。

如果扩展安装前已经打开了 X 页面，请先刷新该标签页。值见也会在发送请求失败时尝试自动重新注入内容脚本。

默认使用 `https://api.openai.com/v1` 和 `gpt-4o-mini`。也可以填写兼容 OpenAI Chat Completions 接口的服务商，例如 DeepSeek、OpenRouter 或自建网关。第一次保存自定义域名时，Chrome 可能会询问额外的网络访问权限。

## 隐私和安全

- API Key 只写入当前浏览器的 `chrome.storage.local`，不会进入 Git 仓库。
- 帖子正文会发送到用户自己填写的 LLM 服务商；使用前请确认该服务商的隐私政策和数据保留规则。
- 帖子内容被视为不可信输入，LLM 提示词明确要求忽略帖子中的任何指令。
- X 采集使用用户当前浏览器的登录态，通过临时非活动标签页读取公开给该用户的页面内容；不绕过 X 的访问控制。
- RSS/Atom 内容会直接发送给用户选择的 LLM 服务商参与评估。
- 自动分析依赖浏览器运行；浏览器关闭或设备休眠时，不能保证每 30 分钟准点执行。
- 当前版本不声称完整覆盖 X 全站；账号和主题搜索结果受 X 页面返回范围及频率限制。

## 设计原则

热门指标只用于候选召回和很小的辅助加分，最终判断以用户的价值需求和内容质量为主。每条推荐都要求给出“为什么值得阅读”和“为什么值得互动”的解释。

## 采集流程

```text
chrome.alarms 每 30 分钟触发
  ├─ 关注账号 → 合并为 X 实时搜索
  ├─ 关注主题 → X 实时搜索
  └─ RSS/Atom → 直接请求 Feed
        ↓
候选归一化、去重、数量控制
        ↓
用户自选 LLM 做价值评审
        ↓
Top 5 + 其他候选 + 浏览器通知
```

## 已知边界

- 浏览器必须运行，X 数据采集需要有效登录态。
- X 页面结构变化可能导致采集失效，需要持续适配。
- 每次扫描会短暂打开非活动的 X 标签页，完成后自动关闭。
- RSS 只读取 Feed 提供的标题和摘要，暂未自动抓取文章全文。
- 当前版本没有服务端账号体系，设置和结果只保存在当前浏览器。
- 如果看到 `Receiving end does not exist`，请刷新 X 标签页并重新加载扩展；这表示内容脚本尚未在该页面运行。
