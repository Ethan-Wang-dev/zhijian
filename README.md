# 值见

> 每半小时，找到真正值得看的内容。

值见是一个 Chrome/Chromium Manifest V3 浏览器扩展。它从 X 全站趋势、指定账号、指定主题和 RSS/Atom 收集候选，再交给用户自己的 LLM，按个人价值需求筛选最多 5 条主推荐，并保留其他候选。

> 0.3.0 起，默认 X 数据源改为第三方 API，不再使用用户的 X 登录态。升级后请重新加载扩展，并在设置中填写 X 数据 API Key；不需要 X 内容时也可以关闭 X 数据源。

## 开始使用

1. 打开 Chrome 的 `chrome://extensions`，开启“开发者模式”。
2. 点击“加载已解压的扩展程序”，选择本项目目录。
3. 打开“值见 → 设置”，填写 OpenAI-compatible LLM 的 Base URL、模型和 API Key。
4. 在“X 数据来源”中保留推荐的 `TwitterAPI.io`，填写该服务的 API Key。
5. 用自然语言描述自己的价值需求，并按需填写 X 账号、主题和 RSS/Atom 地址。
6. 保留“X 全站发现”即可发现尚未关注账号的内容；`WOEID=1` 代表 Worldwide。
7. 点击页面底部“保存全部设置”，再分别测试 LLM 和 X 数据源。
8. 点击扩展弹窗中的“立即扫描全部配置源”，随后打开完整结果面板。

如果只需要 RSS/Atom，可把 X 数据源设为“关闭”，不需要 TwitterAPI.io Key。RSS.app 等服务生成的 X Feed 也可以直接粘贴到 RSS 输入框。

## 结果在哪里

- 扩展弹窗显示上次扫描摘要和 Top 5 快捷入口。
- “打开完整结果面板”展示 Top 5、其他候选、来源统计、推荐理由和互动判断。
- 自动扫描发现新的主推荐时发送浏览器通知；点击通知会打开结果面板。
- X 页面右下角浮层和“只分析当前 X 页面”只是手动辅助功能，不是自动扫描的前提。

## 0.3.0 能做什么

- 每 30 分钟自动运行，不要求用户停留在 X 页面。
- 默认通过 TwitterAPI.io 直接取得公开 X 数据，不读取用户的 X Cookie 或登录态。
- 全站发现：获取一个地区的 30 个当前趋势，由 LLM 按用户价值需求选择最多 3 个，再检索具体帖子。
- 指定账号：把最多 12 个账号合并为一次 Latest 搜索。
- 指定主题：和选中的全站趋势合并为一次 Top 搜索，因此会自然发现未关注账号。
- RSS/Atom：直接读取最多 12 个 Feed。
- 多源候选按来源轮转截取，避免某个来源占满候选额度。
- LLM 按个人相关性、信息增量、影响、可执行性、思考价值、互动价值、证据质量和时效性评分。
- 默认 65 分以上才进入主推荐；每轮最多 5 条主推荐和 10 条其他候选。
- 支持浏览器通知和“有用 / 不太相关”本地反馈。
- 数据源部分失败时，成功取得的内容仍会继续分析，失败原因显示在结果面板。

## 自动发现流程

```text
chrome.alarms 每 30 分钟触发
  ├─ 地区趋势（30 个）→ LLM 选择最多 3 个
  ├─ 选中趋势 + 配置主题 → 1 次全站 Top 搜索
  ├─ 配置账号 → 1 次 Latest 搜索
  └─ RSS / Atom → 直接读取 Feed
                    ↓
          归一化、去重、来源均衡
                    ↓
           LLM 做个人价值评审
                    ↓
       Top 5 + 其他候选 + 浏览器通知
```

这里的“全站发现”是趋势驱动的候选召回，不等于下载或遍历 X 全站。任何可持续方案都必须先缩小候选范围，再做昂贵的内容理解。

## 成本和频率

TwitterAPI.io 当前按返回的帖子数计费，官网在 2026-09-11 显示 `$0.15 / 1,000 tweets`。值见每轮最多执行一次账号搜索和一次主题/趋势搜索，每次文档标注最多返回约 20 条；若两类都启用且每次都返回 20 条，30 分钟扫描的 X 帖子读取费约为 `$0.006/轮`、约 `$8.64/月`，另加趋势请求和 LLM 费用。实际价格以服务商页面为准。

降低成本的方法：

- 没有指定账号时，只会执行主题/趋势搜索。
- 关闭“X 全站发现”可省去趋势请求和趋势选择 LLM 调用。
- 关闭自动扫描后，只在手动点击时运行。
- 只使用 RSS/Atom 时，无需 X 数据 API。

## 风控、隐私和安全

- 默认 API 模式不会登录、点击或模拟操作用户的 X 账号，也不读取 X Cookie，因此不会把自动扫描行为直接归到用户的 X 账号上。
- 这不等于数据链路零风险：第三方 API 仍有自身条款、数据授权、稳定性、价格和停服风险，使用者需要自行确认其合规性。
- “浏览器登录态”仅保留为实验模式。它会打开非活动 X 搜索页，仍可能遇到限流、验证码或账号风控，不建议长期使用。
- LLM Key 和 X 数据 API Key 只保存在当前浏览器的 `chrome.storage.local`；扩展更新时不会被清除，也不会写入 Git 仓库。
- 候选正文会发送到用户选择的 LLM 服务商。使用前请确认该服务商的数据保留和隐私政策。
- 帖子和 Feed 内容都按不可信输入处理；提示词要求模型忽略候选内容中的指令。
- 自动任务依赖浏览器运行。浏览器关闭或设备休眠时，不能保证每 30 分钟准点执行。

## 为什么没有直接抓热门网站

趋势榜网站通常只提供主题名、地区排名和帖子量，不能稳定提供完整帖子及互动字段；部分网站还明确禁止批量提取。它们可以辅助“发现话题”，不能独立完成“判断哪些具体内容值得看”。详细核验见 [X 数据源选择](docs/x-data-sources.md)。

## 已知边界

- 当前全站发现依赖地区趋势，可能漏掉尚未进入趋势的高价值小众内容。
- TwitterAPI.io 是独立第三方服务，并非 X 官方服务；当前适配器依赖其接口和返回结构。
- RSS 当前读取 Feed 提供的标题和摘要，暂未自动抓取文章全文。
- 设置、结果和反馈仅保存在当前浏览器，没有跨设备同步和服务端定时任务。
- 当前反馈只记录在本地，尚未自动更新个人排序权重。
